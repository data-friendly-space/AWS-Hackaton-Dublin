Overview

A human-readable format for encoding R4S social system assessments

The Resilio DSL (.resilio) is a declarative language designed to represent the four core assessments of the Resilience for Social Systems (R4S) methodology:

Actor Assessment

Define system actors with their types, functions, needs, and concerns.

Relationship Assessment

Map interactions between actors with quality ratings and KPIs.

Component Assessment

Evaluate actor importance through production levels and replaceability.

Vulnerability Assessment

Assess actor vulnerabilities against defined risk scenarios.

Design Principles

  • Human-readable: Easy to write and review without specialized tools
  • Declarative: Describe what the system looks like, not how to build it
  • Validatable: Structured format enables automated validation
  • Extensible: Metadata blocks allow custom attributes
  • Interoperable: Exports to JSON, CSV, and visual formats

File Extension

Resilio DSL files use the .resilio extension. MIME type: text/x-resilio

Basic Syntax

Foundational language constructs and conventions

Comments

Single-line comments begin with # or //. Multi-line comments use /* */.

# This is a single-line comment
// This is also a single-line comment

/*
  This is a multi-line comment
  spanning multiple lines
*/

Identifiers

Identifiers are used to reference actors and other entities. They must start with a letter and can contain letters, numbers, and underscores.

identifier ::= [a-zA-Z] [a-zA-Z0-9_]* 
# Valid identifiers
DHO
DistrictHealthOffice
CHW_01
facility_level_2

# Invalid identifiers
# 01_facility  (starts with number)
# health-center  (contains hyphen)

Strings

Strings are enclosed in double quotes. Multi-line strings use triple quotes.

# Single-line string
"District Health Office"

# Multi-line string
"""
This is a longer description
that spans multiple lines and preserves
line breaks and formatting.
"""

Numbers

Numbers can be integers or decimals. Scale values (1-5) are used for assessments.

1        # Integer
3.5      # Decimal
0.8      # Decimal less than 1

Blocks

Blocks group related declarations using curly braces { }.

actor DHO {
    name: "District Health Office"
    type: service_provider
}

Properties

Properties are key-value pairs separated by colons. Each property goes on its own line within a block.

property ::= identifier ":" value
value ::= string | number | enum_value | identifier | list

Lists

Lists are comma-separated values enclosed in square brackets.

kpis: ["Coverage rate", "Response time", "Patient satisfaction"]

System Declaration

Define the overall system context and metadata

Every Resilio file begins with a system declaration that provides context for the assessment.

Syntax

system_decl ::= "system" identifier "{" system_props "}" 
system RMNCAH_Eastern {
    name: "RMNCAH Health System"
    description: """
        Reproductive, Maternal, Newborn, Child, and Adolescent Health
        system serving the Eastern Region.
    """
    region: "Eastern Region"
    country: "Ethiopia"
    sector: health
    subsector: "RMNCAH"
    assessment_date: "2026-01-15"
    version: "1.0"
}

Properties

Property Type Required Description
name string Yes Human-readable name for the system
description string No Detailed description of the system scope
region string No Geographic region of assessment
country string No Country of assessment
sector enum Yes Primary sector: health, education, market, water, protection
subsector string No Specific subsector within the primary sector
assessment_date string No Date of assessment (ISO 8601)
version string No Version number of this assessment

Actor Declaration

Define system actors with their roles, needs, and concerns

Actors are the fundamental entities in the social system. Each actor declaration creates a unique entry in the Actor Assessment.

Syntax

actor_decl ::= "actor" identifier "{" actor_props "}" 
actor DHO {
    name: "District Health Office"
    type: service_provider

    function: """
        Coordinates and oversees health service delivery across the district.
        Manages resource allocation, supervises health facilities, and ensures
        quality standards are maintained throughout the health system.
    """

    needs: """
        Adequate budget allocation from regional health bureau, trained staff,
        medical supplies and equipment, reliable data reporting from facilities,
        transportation for supervision visits.
    """

    worries: """
        Budget cuts reducing service capacity, staff turnover and brain drain,
        supply chain disruptions, disease outbreaks overwhelming capacity,
        political interference in health priorities.
    """
}

Actor Types

The type property must be one of the following values:

service_user
Directly demands, uses, and/or benefits from the goods/services/resources
service_provider
Delivers core goods/services/resources directly to meet user needs
support
Enables or enhances system performance through technical, financial, logistical assistance
regulatory
Sets, enforces, and/or monitors rules, standards, and compliance

Properties

Property Type Required Description
name string Yes Full name of the actor
type enum Yes Actor type (see above)
function string Yes Role and significance within the system
needs string Yes Essential services or conditions the actor expects
worries string Yes Main risks, challenges, or adverse conditions
aliases list No Alternative names or abbreviations
metadata block No Custom key-value pairs for extensions

Example with Metadata

actor CHW {
    name: "Community Health Workers"
    type: service_provider
    aliases: ["Health Extension Workers", "HEWs"]

    function: "Provide primary healthcare services at community level"
    needs: "Training, supplies, supervision, community trust"
    worries: "Lack of supplies, inadequate compensation, security concerns"

    metadata {
        estimated_count: 450
        coverage_area: "Rural kebeles"
        training_level: "Level 3"
    }
}

Relationship Declaration

Define connections and interactions between actors

Relationships capture the flow of goods, services, and resources between actors, along with quality assessments.

Syntax Options

Relationships can be declared using either block syntax or arrow syntax:

Block Syntax (Full)

relationship DHO_to_HealthCenter {
    from: DHO
    to: HealthCenter
    type: output

    goods: """
        Medical supplies, vaccines, essential medicines,
        technical guidance, supervision visits, performance feedback
    """

    quality: stressed

    rationale: """
        Supply deliveries are frequently delayed due to logistics challenges.
        Supervision visits occur less frequently than planned due to
        vehicle shortages and fuel costs.
    """

    kpis: [
        "Supply delivery timeliness (target: <7 days)",
        "Supervision visit frequency (target: monthly)",
        "Stock-out rate (target: <5%)"
    ]
}

Arrow Syntax (Concise)

For simpler relationships, use the arrow syntax:

# Output relationship (actor provides to another)
DHO -> HealthCenter {
    goods: "Medical supplies, supervision"
    quality: stressed
    rationale: "Delayed deliveries due to logistics"
}

# Input relationship (actor receives from another)
HealthCenter <- RegionalBureau {
    goods: "Budget allocation, policy directives"
    quality: good
}

# Bidirectional relationship
HealthCenter <-> Community {
    goods: "Health services | Feedback, utilization"
    quality: good
}

Relationship Types

input
Goods/services/resources flowing into the actor
output
Goods/services/resources provided by the actor

Relationship Quality

good
Functions well for both actors, supports system performance
stressed
Inadequate or imbalanced; doesn't work ideally for both actors
bad
Fails to deliver benefits; doesn't support system objectives
absent
Non-existent but should exist to support system objectives

Properties

Property Type Required Description
from identifier Yes* Source actor (not needed with arrow syntax)
to identifier Yes* Target actor (not needed with arrow syntax)
type enum Yes* Relationship type (inferred from arrow direction)
goods string Yes Specific goods, services, resources exchanged
quality enum Yes Quality assessment of the relationship
rationale string Yes Reason for the quality assessment
kpis list No Suggested key performance indicators

Absent Relationships

Use quality absent to document relationships that should exist but don't. This is critical for identifying gaps in the system.

# Document a missing but needed relationship
PrivatePharmacy -> DHO {
    goods: "Stock reports, disease surveillance data"
    quality: absent
    rationale: """
        Private pharmacies operate independently without reporting to DHO.
        This gap prevents comprehensive disease surveillance and stock
        management across the district.
    """
}

Component Assessment

Evaluate actor importance through production and replaceability

Component assessments measure each actor's contribution to the system and how easily they could be replaced.

Syntax

component DHO {
    goods: "Coordination, supervision, supply distribution"

    production: 4  # High contribution (61-80%)
    replaceability: 5  # Not replaceable

    rationale: """
        The DHO plays a major role in coordinating all health services
        across the district. As the sole government coordination body,
        there is no viable substitute - removal would severely degrade
        the health system's ability to function coherently.
    """
}

# Relevance score is auto-calculated: production × replaceability = 20

Production Scale (1-5)

How much does the actor contribute to the system's overall functioning?

Value Level Description
1 Minimal Peripheral or occasional role (1-20%)
2 Low Limited influence on system performance (21-40%)
3 Moderate Important but not central (41-60%)
4 High Major role in service delivery or flow (61-80%)
5 Very High Core service provider or critical function (81-100%)

Replaceability Scale (1-5)

How easily can the actor be replaced by another actor or mechanism?

Value Level Description
1 Highly replaceable Many viable substitutes; quick switching with minimal disruption
2 Easily replaceable Several viable substitutes; small, manageable disruption
3 Moderately replaceable Alternatives exist; replacement causes noticeable disruption
4 Hard to replace Few substitutes; significant time/cost or quality trade-offs
5 Not replaceable Unique mandate/capacity; removal severely degrades function

Relevance Score

The relevance score is automatically calculated as: production × replaceability

Range: 1-25. Higher scores indicate actors that are both highly productive and difficult to replace.

Vulnerability Assessment

Assess how risk scenarios affect system actors

Vulnerability assessments evaluate each actor against defined risk scenarios using sensitivity, exposure, and capacity metrics.

Syntax

vulnerability DHO @ drought {
    sensitivity: 3    # Moderate impact
    exposure: 4       # High exposure
    capacity: 3       # Moderate coping ability

    rationale: """
        Drought increases demand for health services while simultaneously
        straining resources. The DHO has some emergency protocols but
        limited surge capacity. Budget flexibility allows some adaptation
        but prolonged drought would overwhelm existing coping mechanisms.
    """
}

# Vulnerability score: (sensitivity + exposure) / capacity = (3+4)/3 = 2.3
# Vulnerability level: Low (1.1-8.33)

Sensitivity Scale (1-5)

How badly is the actor affected by the risk?

Value Level Description
1Very LowMinimal impact; function continues almost unchanged
2LowSome disruption, but manageable without major consequences
3ModerateNoticeable impact; performance reduced but still functional
4HighSevere disruption; core functions compromised
5Very HighActor cannot function; total breakdown under shock

Exposure Scale (1-5)

How likely is the actor to be exposed to the risk?

Value Level Description
1Very LowHighly shielded; indirect or negligible exposure
2LowMostly protected; occasional exposure
3ModerateSome protective measures; regular exposure
4HighLimited protection; frequent exposure
5Very HighNo shielding; direct and constant exposure

Capacity Scale (1-5)

How able is the actor to resist, absorb, adapt, or transform because of the risk?

Value Level Description
1Very LowNo coping mechanisms; highly fragile
2LowMinimal coping ability; short-term fixes only
3ModerateSome adaptive capacity; can manage partial shocks
4HighStrong coping and adaptation; can recover quickly
5Very HighHighly resilient; robust and resourceful

Vulnerability Score & Level

Calculated as: (sensitivity + exposure) / capacity

Score Range Level Color Code
0 - 1.0MinimalGreen
1.1 - 8.33LowLight Green
8.34 - 16.66MediumAmber
16.67 - 25.0HighRed

Risk Scenario Declaration

Define the risk scenarios used in vulnerability assessments

Risk scenarios must be declared before they can be referenced in vulnerability assessments.

Syntax

risk drought {
    name: "Severe Drought"
    description: """
        Extended period of below-normal rainfall leading to water scarcity,
        crop failure, and increased food insecurity. Typically lasting
        6-18 months with cascading effects on health, livelihoods, and
        social stability.
    """
    category: climate
    likelihood: likely
    historical: "2015, 2017, 2022"
}

risk disease_outbreak {
    name: "Disease Outbreak"
    description: "Sudden increase in disease cases overwhelming health capacity"
    category: health
    likelihood: possible
}

risk economic_shock {
    name: "Economic Crisis"
    description: "Currency devaluation, inflation, or market collapse"
    category: economic
    likelihood: possible
}

Risk Categories

climate
Weather, climate change related
health
Disease, epidemic, pandemic
economic
Market, financial, livelihood
conflict
Violence, displacement, insecurity
natural
Earthquake, flood, landslide
political
Policy change, governance failure

Likelihood Levels

rare
Unlikely to occur (<10% probability)
unlikely
Could occur but not expected (10-30%)
possible
Might occur (30-60%)
likely
Will probably occur (60-90%)
almost_certain
Expected to occur (>90%)

# Resilio Mapping Assessment
# =============================================================================

system RMNCAH_Eastern {
    name: "RMNCAH Health System"
    description: """
        Reproductive, Maternal, Newborn, Child, and Adolescent Health
        system serving the Eastern Region. This assessment maps the key
        actors, relationships, and vulnerabilities affecting RMNCAH
        service delivery.
    """
    region: "Eastern Region"
    country: "Ethiopia"
    sector: health
    subsector: "RMNCAH"
    assessment_date: "2026-01-15"
    version: "1.0"
}

# -----------------------------------------------------------------------------
# Risk Scenarios
# -----------------------------------------------------------------------------

    name: "Severe Drought"
    description: "Extended rainfall deficit causing water scarcity and food insecurity"
    category: climate
    likelihood: likely

    name: "Disease Outbreak"
    description: "Epidemic requiring surge capacity in health services"
    category: health
    likelihood: possible
}

# -----------------------------------------------------------------------------
# Service Users
# -----------------------------------------------------------------------------

actor PregnantWomen {
    name: "Pregnant Women"
    type: service_user

    function: """
        Primary beneficiaries of maternal health services including
        antenatal care, skilled delivery, and postnatal care.
    """

    needs: """
        Access to quality ANC services, skilled birth attendance,
        emergency obstetric care, postnatal support, nutrition services
    """

    worries: """
        Distance to health facilities, cost of services, lack of
        female health workers, poor quality of care, traditional
        practices conflicting with medical advice
    """
}

# -----------------------------------------------------------------------------
# Service Providers

}

actor NGO_Health {

    function: "Provide technical assistance, funding, and capacity building"
    needs: "Government coordination, community access, funding continuity"
    worries: "Funding cuts, access restrictions, coordination gaps"
}

# -----------------------------------------------------------------------------
# Regulatory Actors
# -----------------------------------------------------------------------------

actor RegionalBureau {
    name: "Regional Health Bureau"
    type: regulatory

    function: "Sets policies, allocates resources, monitors performance"
    needs: "Federal guidance, accurate data, political support"
    worries: "Budget constraints, competing priorities, capacity gaps"
}

# -----------------------------------------------------------------------------
# Relationships
# -----------------------------------------------------------------------------

# DHO Relationships

    replaceability: 5

    replaceability: 4

    replaceability: 3

File Organization

While all declarations can be in a single file, large assessments can be split across multiple files using the @import directive (e.g., @import "actors.resilio").

Grammar Reference

Formal grammar specification in EBNF notation

document        ::= system_decl (risk_decl | actor_decl | relationship_decl | component_decl | vulnerability_decl)*

system_decl     ::= "system" identifier "{" system_props "}"
system_props    ::= (property)*

risk_decl       ::= "risk" identifier "{" risk_props "}"
risk_props      ::= (property)*

actor_decl      ::= "actor" identifier "{" actor_props "}"
actor_props     ::= (property | metadata_block)*
metadata_block  ::= "metadata" "{" (property)* "}"

relationship_decl ::= relationship_block | relationship_arrow
relationship_block ::= "relationship" identifier "{" relationship_props "}"
relationship_arrow ::= identifier arrow_op identifier "{" relationship_props "}"
arrow_op        ::= "->" | "<-" | "<->"

component_decl  ::= "component" identifier "{" component_props "}"
vulnerability_decl ::= "vulnerability" identifier "@" identifier "{" vulnerability_props "}"

property        ::= identifier ":" value
value           ::= string | number | enum_value | identifier | list
list            ::= "[" (value ("," value)*)? "]"

string          ::= '"' characters '"' | '"""' characters '"""'
number          ::= digit+ ("." digit+)?
identifier      ::= letter (letter | digit | "_")*
enum_value      ::= identifier

actor_type      ::= "service_user" | "service_provider" | "support" | "regulatory"
rel_type        ::= "input" | "output"
rel_quality     ::= "good" | "stressed" | "bad" | "absent"
risk_category   ::= "climate" | "health" | "economic" | "conflict" | "natural" | "political"
likelihood      ::= "rare" | "unlikely" | "possible" | "likely" | "almost_certain"
sector          ::= "health" | "education" | "market" | "water" | "protection"
